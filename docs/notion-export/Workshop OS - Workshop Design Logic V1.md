# Workshop OS - Workshop Design Logic V1

# Purpose

The Workshop Design Engine converts a diagnosis into a bespoke workshop design.

Its role is to select the most appropriate activities from the Activity Library and arrange them into a structured workshop agenda.

The Workshop Design Engine is responsible for:

- Activity selection
- Activity sequencing
- Time allocation
- Workshop structure
- Output generation

The goal is not to recommend a predefined workshop.

The goal is to design a workshop tailored to the user's specific challenge, desired outcome and constraints.

# Design Principles

## Principle 1

Design the workshop around the challenge, not the activity.

Activities exist to help solve a problem.

Activities should never be selected simply because they are popular or familiar.

---

## Principle 2

The workshop should move the team forward.

Every activity should create an output that helps the next activity.

The workshop should feel like a progression rather than a collection of unrelated exercises.

---

## Principle 3

Keep workshops outcome focused.

Activities should contribute directly to the desired outcome identified during diagnosis.

---

## Principle 4

Respect constraints.

The generated workshop must fit within:

- Available time
- Participant count
- Remote or in-person delivery
- Stakeholder availability

---

# Activity Selection Rules

## Rule 1

Primary Stage activities should occupy approximately 60–70% of workshop time.

Example:

Primary Stage = Evaluate

90 minute workshop

Approximately 55–65 minutes should focus on Evaluate activities.

---

## Rule 2

Secondary Stage activities should occupy approximately 20–30% of workshop time.

Example:

Secondary Stage = Decide

90 minute workshop

Approximately 20–25 minutes should focus on Decide activities.

---

## Rule 3

Reserve approximately 10% of workshop time for synthesis and actions.

Example:

90 minute workshop

10 minutes reserved for summary, actions and next steps.

---

# Input Rules

Activities should only be selected when the required inputs are available.

Example:

Journey Map requires:

- Existing research
- User feedback
- Analytics

If those inputs do not exist:

Do not recommend Journey Map.

Instead recommend:

- Assumption Collecting
- Prototype Persona

---

# Output Rules

Activities should be sequenced so outputs feed the next activity.

Example:

Problem Statement

↓

How Might We

↓

Crazy Eights

The output of one activity becomes the input of the next.

---

# Future Vision

Future versions of the Workshop Design Engine may:

- Optimise activity combinations using AI
- Learn from workshop outcomes
- Adapt agendas based on participant behaviour
- Generate alternative workshop designs
- Generate workshop variants for different audiences

Workshop Design Logic V1 provides a transparent and explainable foundation that can later evolve into a more advanced workshop generation system.
